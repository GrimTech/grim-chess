# Grim Chess architecture and team contract

Grim Chess is a chess *training* platform: zero knowledge → master/grandmaster strength, with progress measured
against real-world rating benchmarks. It is not a replacement for Lichess/Chess.com.

## Stack (fixed)
- **Web**: React 19 + Vite 8 + TypeScript + react-router-dom 7 (data router). **No Next.js.** Plain CSS using the design
  system in `apps/web/src/styles/{tokens,components}.css` (source: `docs/design/`). Icons: `lucide-react`.
- **Board**: `apps/web/src/components/Board.tsx` (lichess chessground + chess.js). Every feature uses it.
- **Engine**: Stockfish 19 WASM (`stockfish` npm, lite single-threaded build, run in a Web Worker) for strong levels
  and analysis; in-house engine `packages/engine` for human-like low-rated bots. Facade: `apps/web/src/lib/engine.ts`.
- **Server**: Node 24 running TypeScript directly (native type stripping: only erasable syntax, no `enum`, no
  parameter properties, no namespaces; relative imports use `.ts` extensions). `node:sqlite` for storage, `ws` for
  WebSockets, `node:http` (no framework). One process serves API + WebSocket + built web app.
- **Shared**: `packages/core` (types, Glicko-2, Lichess accuracy formula, FSRS-4.5, rating estimate, daily plan).
- **Deploy**: Docker image on Fly.io (`deploy/Dockerfile`, `fly.toml`), SQLite on a Fly volume at `/data`.
- **License**: AGPL-3.0-or-later (Stockfish and chessground are GPL-3; puzzle and openings data are CC0 from Lichess).

## Content formats
- Skill graph: `knowledge-base/03-chess-knowledge/skill-graph.json` (`SkillGraph` in `packages/core/src/types.ts`).
- Lessons: one JSON file per lesson, `content/lessons/<track>/<id>.json`, shape `Lesson` (types.ts). `skillIds` must
  exist in the skill graph. All FENs must be legal and all `solution` SAN must be legal from the given FEN;
  `scripts/validate-content.ts` (run with `npm run validate:content`) enforces this.
- Puzzles: CSV columns `id,fen,moves,rating,rd,popularity,plays,themes,openings,gameUrl`. `moves` are UCI separated by
  spaces; moves[0] is played by the opponent automatically, then the learner plays moves[1], moves[3], …

## HTTP API (server)
Auth: an httpOnly cookie `gc_session`. `GET /api/me` creates a guest device account if no session exists.
All bodies JSON. Errors: `{ "error": string }` with 4xx/5xx.

| POST `/api/auth/login` / `/api/auth/logout` | `{username,password}` / – | `Me` / 204 |
| PATCH `/api/profile` | `Partial<Profile>` | `Me` |
| GET `/api/server-info` | | `{mode:'cloud'|'lan'|'dev', version, lanUrls[], puzzleCount}` |

| GET `/api/curriculum/lessons?track=` | | `LessonIndexEntry[]` |

Rating pools updated by the server from events: `puzzle` (opponent = puzzle rating/RD), `bot` (opponent = bot
rating/RD from `BOT_LEVELS`), `online` (opponent = other player's online rating; rated games only),
`assessment`. `estimate` is recomputed with `estimateRating()` after each batch.

## WebSocket protocol (`/ws`, JSON messages, field `t` = type)
Used for internet play (Fly deployment) and LAN play (same server run locally with `npm run lan`, bound to 0.0.0.0).

Client → server: `{t:'seek', tc:{initial,increment}, rated}` · `{t:'cancelSeek'}` ·
`{t:'createRoom', tc, color:'white'|'black'|'random'}` · `{t:'joinRoom', code}` · `{t:'move', gameId, uci, ply}` ·
`{t:'resign', gameId}` · `{t:'offerDraw', gameId}` · `{t:'acceptDraw', gameId}` · `{t:'declineDraw', gameId}` ·
`{t:'rematch', gameId}` · `{t:'rejoin', gameId}` · `{t:'ping'}`

Server → client: `{t:'lobby', players, seeks}` · `{t:'roomCreated', code}` · `{t:'gameStart', game}` ·
`{t:'gameState', game}` · `{t:'drawOffered', gameId, by}` ·
`{t:'gameEnd', gameId, result:'1-0'|'0-1'|'1/2-1/2', reason, ratingChange?:{white:number,black:number}}` ·
`{t:'rematchOffered', gameId}` · `{t:'error', message}` · `{t:'pong'}`

`GameView = {id, white:{name,rating}, black:{name,rating}, fen, moves:string[] /*UCI*/, clocks:{white:ms,black:ms},
turn:'white'|'black', status:'active'|'ended', result?, reason?, tc:{initial,increment}, rated,
you:'white'|'black'|'spectator', serverTime:number}`. The server validates every move with chess.js and runs the
clocks; a player who disconnects has 60 s to reconnect (`rejoin`) before the game is scored as abandoned.
Room codes are 6 uppercase letters/digits (no ambiguous characters).

## Engine facade (`apps/web/src/lib/engine.ts`)
`BOT_LEVELS`, `bestMove(fen,{level})`, `analyse(fen,{depth,multipv})`, `analyseGame(fens)`, `stopEngine()`.
Scores in `analyse` are from the side to move; `analyseGame` returns White-POV centipawns (mate = ±1000).

## Measurement
`knowledge-base/04-assessment/platform-measurement-model.md` defines the estimate. `data/benchmarks.json` holds
per-band benchmarks (ACPL, accuracy, puzzle rating, percentiles, conversions). Title "equivalents" are shown as
"CM/FM/IM/GM-equivalent strength", never as titles; real titles require FIDE-rated over-the-board norms.
